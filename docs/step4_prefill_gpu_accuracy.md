## 参考计算与覆盖范围

参考实现按实际 region 编号收集有效 token，保留跨批次原始输入；每次重新计算权重、分子、分母与最终加权平均，不复用 kernel 的任务前缀计算。FP8 参考结果依次经过 FP32 → BF16 → FP8 转换，与生产存储路径一致。另行检查 slot 拥有者不重复、完成后释放、未完成时保留状态。

61 项包含：

- FP16、BF16、FP32 输入；region 大小 1、3、8、16；维度 17、65、127、256。
- 多请求、空请求、空批次、非零请求起始偏移、批次末尾填充行。
- 多次分块累计、旧尾部完成与新尾部产生、reset、脏空闲 slot 的重新初始化。
- 首尾 token 无效、全部无效、大幅度 logits，以及 512、4096、16384 token 输入。
- 64 个未完成 region 同时申请 slot、容量不足时停止 update。
- 反向映射缺失、指向空位、越界或指向其他 region；分别覆盖继续累计与本次完成。

## 验证中修复的 slot 问题

首次运行 53 项，通过 51 项：一项暴露 slot 状态丢失，另一项是下面记录的 FP8 舍入差异。

具体场景：region 10 的旧累计状态在 slot 3，slot 0 为空，反向映射失效。如果查找过程遇到 slot 0 就立即占用，会给同一 region 重复分配并丢失 slot 3 的历史贡献。

修复后的准备阶段先检查实际拥有者表，找回旧 slot 并修复反向映射。只有确实不存在旧 slot 且 region 未完成时，才申请并初始化空位。完成任务也执行映射修复，以便 update 读取旧状态。新增的 8 项映射场景和原失败场景均已通过；update 仍只调用一次。

## FP8 舍入边界差异

固定随机种子 1051，16,384 token、region 大小 8、维度 256。524,288 个输出元素中，region 1452 的第 8 列（从 0 计数）与 PyTorch 参考不同：

| 阶段 | kernel | PyTorch 参考 |
| --- | --- | --- |
| FP32 加权平均 | `0.052612289786338806` | `0.052612341940402985` |
| 转 BF16 后 | `0.052490234375` | `0.052734375` |
| 转 FP8 后 | `0.05078125` | `0.0546875` |

量化前的微小差异落在 BF16 舍入边界两侧，随后使 FP8 输出相差 `0.00390625`，超出严格容差。该用例量化前相对 PyTorch FP32 参考的最大绝对误差为 `7.152557373046875e-7`；相对 FP64 参考为 `5.335189854349665e-7`。

用仓库 HEAD 中修改前的 prefill 实现复跑同一输入，旧实现与当前实现的全部 FP8 输出逐位一致。旧实现仅移除了 GPU 不接受的 NPU `compile_mode` 启动参数，计算与分组逻辑保留。因此，此用例的差异并非本次任务划分和单次 update 改造引入；目前保留原计算方式，并如实记录严格检查失败。
